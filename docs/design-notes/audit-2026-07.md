## 1. Scope and method

Audit of the whole engine at SHA `268fe4108e44a8856a98b1d8f84684e3e325d2c4`
(clean tree), run while integration is blocked on the consumer. Charge: is the
implementation as complete as its own docs claim; half-implementations; proof
of soundness; TPtH-vs-generic separation; multi-consumer reuse. Explicitly out
of scope: performance, security threat-modeling (one trusted human user,
trusted callers).

Method: 3 reconnaissance agents (docs, code, boundary), then 8 finder agents
(core algebra, negation, surface, fixture/replay, self-check guards, doc-truth,
boundary, consumer-#2 walkthrough) each carrying the dedupe corpus
(`followups-2026-07.md` F1–F6 + the known-accepted list), then 3 cross-assigned
refute-by-default verifiers re-opening every anchor, then a red-pen pass over
this document. Ground truth was taken from a full gate run, not agent claims:

- `cargo xtask gate` — **PASSED, 16 steps green** (receipt
  `out/greengate/audit-2026-07/receipt.json`, verdict `green` at the audit SHA).
- nextest: **717 tests run, 717 passed, 2 skipped** (the two documented
  `#[ignore]`s).
- `xtask loc`: **28,160** code lines under `crates/*/src`; `WARNING 28160
  exceeds the soft cap of 25000` printed, gate passes (hard cap 40,000).
- boundary guard: 117 files scanned, 0 allowlisted debt sites, green.

Every CRITICAL/HIGH/MEDIUM from the prior red-teams was independently
re-verified as fixed; the accepted F1–F6 remainders were re-verified byte-exact
as documented (no regressions, no silent fixes) — see §9.

## 2. Verdict

**The engine is real, and its machine-checked claims hold.** No blocker was
found: no half-implemented op, no `todo!()` body, no unsound certain-layer
path, no nondeterminism in a judgment, and the gate/CI/fixture/schema apparatus
genuinely enforces what it scans. The prior red-team fixes all held. Where the
audit looked for vacuous tests it mostly found real ones — the support lattice
is property-proven, the killed-form renames are fully enumerated, fixtures are
full-response JSON-exact on success paths, and the mutation harness census is
arithmetically sound.

**The dishonesty that exists is almost all in prose, and it is systematic:**
the DL-0021 and ec92efd wiring waves updated code, fixtures, and generated
references but no hand-written surface, so the top-of-repo docs a cold reader
must trust (AGENTS.md, PLAN's current-state, the vendored contract §3.1, the
migration worked example) still teach the pre-wiring world. Beyond staleness,
six self-checking guards are narrower than the claims they back (§5), the expert
tier of the surface lane can silently destroy author text (the one place koan
4 is live-violated), the grade channel diverges from spec 02 §2, the shipped
negation semantics diverge from spec 02 §4 and DL-0020's own wording, and the
craft **policy** tier is the one place the DL-0017 separation is not yet real
(consumer `D-nnnn` defaults compiled into engine src; the declared data channel
write-only). None of this blocks integration mechanically — but the contract
declares itself outranking the code while contradicting it, which is the wrong
state to vendor from.

## 3. Confirmed findings — by root cause

guard foolable by a realistic edit). MINOR = proof-gap or misleading staleness.
No BLOCKERs were found. REUSE and POLICY are separate axes (§6, §7).
